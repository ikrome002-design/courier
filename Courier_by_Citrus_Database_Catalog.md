## Catalog conventions

Unless a row explicitly says otherwise, every table uses `id uuid PRIMARY KEY` generated as UUIDv7, `created_at timestamptz`, and `updated_at timestamptz`. Tenant-owned rows contain `merchant_id uuid NOT NULL REFERENCES merchants(id)`. Branch-owned rows also contain `branch_id uuid NOT NULL` with a same-merchant composite constraint. Mutable aggregates contain `aggregate_version bigint NOT NULL DEFAULT 1`. Public API identifiers are UUIDs; sequential IDs are never exposed. Monetary fields are `bigint *_minor` with `char(3) currency`.

Every migration must specify exact foreign-key delete behavior, query-driven indexes, RLS policy, data backfill, validation query, rollback limits, and retention class. “Soft delete” means a `deleted_at` lifecycle marker only; append-only financial, proof, state-history, integration-evidence, and audit records are never soft-deleted as a substitute for correction.

## Mandatory schema lint rules

- Every tenant table has `merchant_id`; branch and organization ownership must match the same merchant.
- Every public lookup has `(merchant_id, public_id)` or equivalent scoped index.
- No `float`/`double` monetary columns and no ambiguous money column named only `amount`.
- `delivery_requests` cannot contain a generic mutable `status`, assignee fields, or refund/dispute state.
- Only one canonical credential, webhook, invoice-line, and role-grant authority exists.
- History/audit/ledger/event tables reject application UPDATE and DELETE.
- Every active/effective-dated version has non-overlap constraints or transactionally enforced equivalent.
- Every provider reference and idempotency identity has a unique constraint appropriate to its scope.
- Duplicate table declarations, plural/case aliases, and competing ORM models fail CI.
- Projection tables are labeled read-only/rebuildable and have no API mutation route.
